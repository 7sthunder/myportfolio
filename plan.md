## 4. How it works (read before changing anything)

### 4.1 Data pipeline

1. **Offline** (`npm run portrait:prepare`):
   1. MODNet portrait matting produces the matte. The largest connected component is kept, and two scooter mirrors are explicitly excluded.
   2. Depth Anything V2 (small) produces depth, normalised inside the subject.
   3. CLAHE is applied to the luminance.
   4. Everything is packed into one **opaque** PNG.

   It's opaque on purpose: if the matte lived in the alpha channel, canvas premultiplication would destroy the data in transparent pixels.
2. **Runtime**:
   1. The PNG is fetched and decoded in a Web Worker, with `colorSpaceConversion: 'none'` because the channels are data, not colours.
   2. The worker builds feature maps:
      - a rim map from a distance transform
      - feature edges from Sobel filters on luminance and depth
      - a cumulative density function (CDF)
   3. The worker samples N particles, as described in §4.2.
   4. The particles are uploaded as BufferAttributes on a single `THREE.Points`.

### 4.2 Particle attributes (per particle)

| Attribute | Contents |
|---|---|
| `position` (vec3) | Portrait position in **local space** |
| `aSphere` (vec4) | xyz = globe target; w = horizontal slice (band) index |
| `aScatter` (vec3) | Intro dust position, normalised to [-1, 1]³ (mapped to the viewport in the shader). About 0.12% are "lens" particles (bokeh). |
| `aRandom` (vec4) | x = size, y = brightness, z = phase, w = stagger |
| `aShade` (vec4) | x = rim, y = feature edges, z = matte, w = depth |

**Local space:**
- x points right, y up, z toward the viewer.
- The map spans **2 units vertically**.
- x = 0 is the head centre, and y = 0 is the map's vertical centre.

**Globe targets** use a Fibonacci lattice **matched by height rank**: the top of the hair maps to the top of the globe, and the shoulders to the bottom. That is what makes the morph read as horizontal slices spinning into latitude rings.

### 4.3 Shader logic (`src/particle-portrait/shaders/particles.js`, vertex shader `main()`)

Each frame, the vertex shader applies these steps in order:

1. Adds a tiny **idle drift** (`uDrift`).
2. If `uMorph > 0`, runs `toSphere()`. This is the portrait → globe morph:
   - Cylindrical twist around the vertical axis, with neighbouring bands counter-rotating.
   - Differential "galaxy" swirl.
   - Slices compressed into thin discs, travelling toward the per-band globe latitude `uBandSphere[]`.
   - It is exactly the identity at m = 0 and exactly the globe at m = 1.
3. Applies `modelMatrix`. The group transform comes from the layout plus the scroll state.
4. **Formation**: `mix(scatter, world, smoothstep(f))` with a small stagger (0.16), so the cloud contracts coherently.
5. Samples the **interaction field** at the particle's screen position: GB channels give the displacement, R gives the sparkle.
6. Computes **depth of field**: circle of confusion = `uAperture·|1 − focus/dist| + uBlur`, with energy conservation `(sharp/size)²`. Lens particles get an explicit bokeh boost.
7. Computes **brightness**: an exponential distribution `0.003 + 0.085·(−ln(1−r))` (measured from the reference). It's multiplied by `(1 + uRim·rim² + uFeature·edges)`, the matte, the depth fade, a twinkle, and the **cursor light** (Gaussian around `uPointer`, stronger on the rim).

The fragment shader draws:
- crisp particles as a soft-edged dot plus a faint halo
- defocused particles as a flat bokeh disc

Blending is additive. Depth test and depth write are both off.

### 4.4 Frame loop (`ParticlePortrait.update()`)

The loop only writes uniforms; there are no per-particle CPU loops and no framework state. Each frame it:
- Reads `this.state.shift` and `this.state.morph` (0..1, set by ScrollTrigger in `main.js`).
- Blends the group transform hero → about by `shift`, then → globe by `pm = easeInOutCubic(morph / 0.72)`.
- Sets the tilt: `rotation.x += tilt·sin(π·em)`. Sets the roll: `rotation.z = −0.13·sin(π·em)`.
- Accumulates the swirl phase only mid-morph, and resets it at the ends.
- Rotates the globe slowly once the morph is complete.
- Smooths the pointer (light and parallax), then updates the interaction field. The field pass is skipped once it has fully decayed.

### 4.5 Timelines

**Intro** (time based; `ParticlePortrait.intro()` + `main.js`):

| Time | What |
|---|---|
| 0 → 1.8 s | Dust appears (`intro`, ease power1.out) |
| 0.9 → 3.35 s | Formation (power1.inOut) |
| 0.8 → 3.4 s | Aperture 18 → 3.5 (focus pull) |
| 1.9 → 3.6 s | Extra blur 4 → 0 |
| 1.2 s | Name letters blur in, stagger 0.035 |
| 1.6 s | Designation letters blur in, stagger 0.018 |

**Scroll** (one scrubbed timeline over `[data-pp-experience]`; 1 timeline unit = 100vh of scroll). The page sections are hero 100vh + about 100vh + globe 160vh, which gives 260vh of scroll.

| Scroll units | What |
|---|---|
| 0.05 → 1.00 | `shift` 0 → 1 (power2.inOut): bust slides right and grows |
| 1.05 → 1.80 | `morph` 0 → 1 (linear): slices → discs → rings → globe |
| 1.80 → 2.60 | Ring text spins +32° with scroll (plus a slow time drift) |
| Morph 0.84 → 1 | Ring text fades in and unblurs (in a `gsap.ticker` callback in `main.js`) |

### 4.6 Particle budget

`particleBudget()` keeps a constant density of **0.2 particles per CSS px²** of the on-screen hero bust. Particle size scales with the bust (0.78–1.1×), and density compensates for the size change.

At load, the module generates enough particles for the largest viewport the screen allows (including the rotated orientation on touch devices). After that it uses `setDrawRange` to thin them for the current size. Because particles are in random order, any prefix is an even subsample.

**Original notes (kept for reference):**

**Where it stands.** The last comparison is `reference/captures/compare_discs3.jpg` (top row: reference at 7.0, 7.5, 7.75, 8.0, 8.25 s; bottom row: ours at s1.20 … s1.55).
- The slicing "cut" at the start already matches well.

**What still differs from the reference:**
1. The reference's mid-morph discs are **brighter and denser** than the portrait. Ours look fainter and more diffuse.
2. The reference shows **2 thin, compact head discs (upper right) + 1 large tilted shoulder disc, with a clear empty gap between them**. Ours is a more evenly spaced stack.
3. In the reference the vortex stays **right of centre** during 7.5–8.0 s (disc centres at about 59% across). Ours glides to the centre earlier.
4. The reference's ring stage (8.25 s) shows **distinct bright rings with gaps**. Ours rings are softer.

**Knobs, all in `src/particle-portrait/shaders/particles.js` → `toSphere()` unless noted:**
- **Disc thickness.** The line `y = mix(y, center + (y - center) * 0.3, w * 0.85);` controls it. Try `0.18` and `w * 0.95` for thinner discs.
- **When slices reach their latitude / radius.** Height uses `k = smoothstep(0.12, 0.75, t)`; radius uses `smoothstep(0.4, 0.95, t)`.
- **Gap between head and shoulders.** Spread the band centres mid-morph, e.g. `center += (center - 0.0) * 0.25 * w;`. Alternatively try `bands: 5` in `DEFAULT_SAMPLING` (`src/particle-portrait/sampling.js`, max 8).
- **Brightness mid-morph.** Make `toSphere()` also output `w`, for example via an `out float` parameter, then in `main()` multiply the brightness by `(1.0 + 0.6 * w)`.
- **Vortex staying right of centre longer.** In `ParticlePortrait.update()`, change `pm = easeInOutCubic(clamp(morph / 0.72))` to `easeInOutCubic(clamp((morph - 0.15) / 0.75))`.
- **Crisper rings near the end.** Keep the compression active later. Replace `w` in the compression line with `smoothstep(0.15, 0.4, t) * (1.0 - smoothstep(0.88, 1.0, t))`.
- **Tilt and roll.** `tilt` option (default 0.3) and `rotation.z = -0.13 * mid` in `update()`.

import gsap from 'gsap';
import { ScrollTrigger } from 'gsap/ScrollTrigger';
import { ParticlePortrait } from '../lib/particle-portrait';
import { CometCursor } from '../lib/CometCursor';
import { splitText } from '../lib/text';
import './particle-portrait.css';

gsap.registerPlugin(ScrollTrigger);

export default function ParticlePortraitHero() {
  const root = useRef(null);
  const stage = useRef(null);
  const ring = useRef(null);
  const ringPath = useRef(null);
  const nameEl = useRef(null);
  const roleEl = useRef(null);
  const aboutEl = useRef(null);

  useEffect(() => {
    const layoutRing = (layout) => {
      const el = ring.current;
      const fontSize = parseFloat(getComputedStyle(el).fontSize) || 24;
      const r = layout.globe.radiusPx + fontSize * 0.42;
      const half = Math.ceil(r + fontSize * 1.5);
      el.setAttribute('viewBox', `${-half} ${-half} ${half * 2} ${half * 2}`);
      el.style.width = el.style.height = `${half * 2}px`;
      ringPath.current.setAttribute('d', `M 0 ${-r} A ${r} ${r} 0 1 1 0 ${r} A ${r} ${r} 0 1 1 0 ${-r}`);
    };

    const portrait = new ParticlePortrait(stage.current, {
      map: '/portrait/portrait-map.png',
      meta: '/portrait/portrait-map.json',
      onLayout: layoutRing,
    });
    const cursor = new CometCursor(); // optional: remove if the portfolio has its own cursor
    const ringState = { spin: 0, drift: 0 };

    const ctx = gsap.context(() => {
      const nameChars = splitText(nameEl.current);
      const roleChars = splitText(roleEl.current);
      gsap.set([...nameChars, ...roleChars], { opacity: 0, filter: 'blur(10px)' });
      const intro = gsap
        .timeline({ paused: true })
        .to(nameChars, { opacity: 1, filter: 'blur(0px)', duration: 1.1, ease: 'power2.out', stagger: 0.035 }, 1.2)
        .to(roleChars, { opacity: 1, filter: 'blur(0px)', duration: 1.1, ease: 'power2.out', stagger: 0.018 }, 1.6);
      portrait.ready
        .then(() => {
          intro.add(portrait.intro(), 0);
          intro.play(0);
        })
        .catch(() => intro.progress(1));

      gsap
        .timeline({ scrollTrigger: { trigger: root.current, start: 'top top', end: 'bottom bottom', scrub: 1 } })
        .to(portrait.state, { shift: 1, ease: 'power2.inOut', duration: 0.95 }, 0.05)
        .to(portrait.state, { morph: 1, ease: 'none', duration: 0.75 }, 1.05)
        .to(ringState, { spin: 32, ease: 'none', duration: 0.8 }, 1.8)
        .to({}, { duration: 0.01 }, 2.59);

      const words = splitText(aboutEl.current, 'words');
      gsap.fromTo(words, { opacity: 0.16 }, {
        opacity: 1, ease: 'none', stagger: 0.1,
        scrollTrigger: { trigger: aboutEl.current, start: 'top 92%', end: 'bottom 48%', scrub: 0.6 },
      });
    }, root);

    // Same logic as the gsap.ticker callback at the bottom of src/main.js.
    let ringValue = -1;
    const tick = (_, deltaMs) => {
      const t = Math.min(1, Math.max(0, (portrait.state.morph - 0.84) / 0.16));
      const v = t * t * (3 - 2 * t);
      if (v <= 0) { ringState.drift = 0; if (ringValue === 0) return; } else ringState.drift += (deltaMs / 1000) * 2.4;
      ring.current.style.transform = `translate(-50%, -50%) rotate(${8 + ringState.spin + ringState.drift}deg)`;
      if (Math.abs(v - ringValue) < 0.002) return;
      ringValue = v;
      ring.current.style.opacity = v.toFixed(3);
      ring.current.style.filter = v > 0.995 ? 'none' : `blur(${((1 - v) * 10).toFixed(2)}px)`;
    };
    gsap.ticker.add(tick);

    return () => {
      gsap.ticker.remove(tick);
      ctx.revert();
      cursor.dispose();
      portrait.dispose();
    };
  }, []);

  return (
    <div className="pp-experience" ref={root}>
      <div className="pp-stage" ref={stage}>
        <svg className="pp-ring" ref={ring} aria-hidden="true" focusable="false">
          <defs><path id="pp-ring-path" ref={ringPath} d="M0 -1 A1 1 0 1 1 0 1 A1 1 0 1 1 0 -1" /></defs>
          <text><textPath href="#pp-ring-path" startOffset="75%" textAnchor="middle">Available everywhere</textPath></text>
          <text><textPath href="#pp-ring-path" startOffset="25%" textAnchor="middle">Working globally</textPath></text>
        </svg>
      </div>
      <div className="pp-content">
        <section className="pp-hero" aria-label="Introduction">
          <h1 className="pp-hero__name" ref={nameEl}>Aadhi Narayanan</h1>
          <p className="pp-hero__role" ref={roleEl}>
            <span className="pp-role__line">Software Developer /</span>{' '}
            <span className="pp-role__line">Full Stack Developer</span>
          </p>
        </section>
        <section className="pp-about" aria-label="About">
          <p className="pp-about__text" ref={aboutEl}>
            I turn ambitious ideas into fast, reliable web products. Frontend, backend, performance — as a
            technical partner for startups, founders and product teams.
          </p>
        </section>
        <section className="pp-globe" aria-label="Availability">
          <p className="pp-sr-only">Available everywhere. Working globally.</p>
        </section>
      </div>
    </div>
  );
}

## 9. Decisions already made (don't undo without a reason)

- **Brightness = an exponential distribution**, measured from the reference histograms. A power curve looked like a flat haze.
- **Energy conservation `(sharp/size)²`** for defocus. Anything weaker made the gathering cloud brighter than the finished portrait; the reference cloud is faint.
- **Small formation stagger (0.16) with smoothstep easing.** Big staggers made the portrait "snap" in instead of focusing in.
- **A minimum point size of 2 device px with no energy penalty.** Smaller points miss pixel centres and flicker or disappear.
- **The cursor field is a decaying screen-space texture**, not GPGPU physics. Restoring to rest is exact and smooth, it costs one tiny pass, and the pass is skipped when idle.
- **Opaque PNG with data channels** and decoding with `colorSpaceConversion: 'none'`.
- **Globe targets matched by height rank**, which creates the slice → ring morph.
- **Particle budget based on the bust's area, with draw-range thinning**, so the look stays consistent across screens with no re-sampling on resize.
- **Sampling in a worker and `compileAsync`**, so the main thread stays free during load.

## 10. Known issues and gotchas

- Vite HMR can reload the page in the middle of a capture right after you edit files. The capture tool retries; if it still fails, run it again.
- Scroll captures wait 2.2 s per state because of `scrub: 1` smoothing. Seeking the intro is instant.
- Two background servers (ports 5173 and 4173) may still be running on the old machine. They don't matter on the new device.
- Fonts load from Google Fonts. Without internet, a system font is used and text widths change slightly.
